### 2.2 目标用户细分

**Segment 1: 开发者 (Primary)**

| 属性 | 描述 |
|-----|------|
| 规模 | ~60% 目标用户 |
| 特征 | 每天使用 AI 写代码、debug、学习 |
| 痛点 | 重复问技术问题、代码片段散落 |
| 渠道 | GitHub、V2EX、Twitter、HN |
| 付费意愿 | 高 ($10-20/月) |

**Segment 2: 内容创作者 (Secondary)**

| 属性 | 描述 |
|-----|------|
| 规模 | ~25% 目标用户 |
| 特征 | 使用 AI 写文案、做内容 |
| 痛点 | 好 prompt 没保存、重复调试 |
| 渠道 | 小红书、即刻、Twitter |
| 付费意愿 | 中 ($5-15/月) |

**Segment 3: 研究/其他 (Tertiary)**

| 属性 | 描述 |
|-----|------|
| 规模 | ~15% 目标用户 |
| 特征 | 学术研究、专业领域使用 |
| 痛点 | 知识归档、追踪讨论 |
| 渠道 | 专业社区 |

## 3. 定价策略

### 3.1 定价模型

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Free                    Pro                    Team        │
│  ────                    ────                   ────        │
│  $0                      $10/月                 $20/人/月    │
│                          ($96/年)               (未来)      │
│                                                             │
│  • 100 知识片段          • 无限知识片段          • Pro 全部   │
│  • 基础搜索              • 向量语义搜索          • 团队共享   │
│  • 手动保存              • 浏览器插件            • 管理后台   │
│                          • 自动推荐              • 权限管理   │
│                          • 可执行技能                        │
│                          • 云同步                            │
│                          • 优先支持                          │
│                                                             │
│  目标: 体验产品          目标: 核心用户          目标: 企业   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 定价依据

| 参考点 | 价格 |
|-------|------|
| Mem.ai Pro | $15/月 |
| Notion AI | $10/月 |
| ChatGPT Plus | $20/月 |
| GitHub Copilot | $10/月 |

**定价 $10/月 的理由:**
- 低于 Mem.ai，形成价格优势
- 与 Notion AI 持平，用户可接受
- 是 ChatGPT Plus 的一半，心理门槛低
- 覆盖 LLM API 成本 + 合理利润

### 3.3 付费转化漏斗

```
免费注册 → 激活 → 留存 → 付费

100%     50%    20%    5%

转化策略:
─────────
• 注册 → 激活: 引导保存第一个知识
• 激活 → 留存: 推送相关知识提醒
• 留存 → 付费: 达到 100 条限制时提示升级
```

## 8. 风险与应对

### 8.1 风险矩阵

| 风险 | 可能性 | 影响 | 应对 |
|-----|-------|------|------|
| 用户不愿手动保存 | 高 | 高 | 优先做浏览器插件自动采集 |
| 提炼质量不满意 | 中 | 高 | 允许编辑，持续优化 prompt |
| ProductHunt 效果不好 | 中 | 中 | 不依赖单一渠道 |
| 竞品快速跟进 | 低 | 中 | 深耕差异化，建立用户基础 |
| Chrome 插件审核慢 | 中 | 中 | 提供手动安装 |

### 8.2 Plan B

**如果 6 个月 MAU < 5000:**
1. 重新审视定位，是否够尖锐
2. 深入用户访谈，理解为什么不用
3. 考虑 pivot：
   - 专注单一场景 (如只做代码片段)
   - 转向企业市场
   - 作为插件集成到其他产品

**如果付费转化 < 2%:**
1. 重新设计免费/付费边界
2. 降低价格测试
3. 增加付费独占功能
