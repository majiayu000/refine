# Refine - 4 周执行路线图

> 版本: v1.0 | 状态: 可执行 | 更新: 2026-02-10

---

## 1. 本轮目标

在 4 周内把 Refine 从“可采集与可搜索”推进到“可主动复用”：

1. 补齐扩展输入态推荐闭环（而不是只做手动提取）。
2. 提升搜索质量（关键词 -> 语义混排）。
3. 建立基础增长度量（激活、推荐曝光、点击、复用）。
4. 夯实上线安全基线（鉴权默认开启、基础风控）。

---

## 2. 北极星与阶段 KPI

### 2.1 北极星指标

- `知识复用率` = 7 天内被再次使用的知识数 / 新增知识数

### 2.2 4 周阶段目标

- `推荐 CTR` >= 12%
- `激活率` (安装后 24h 内完成首条入库) >= 55%
- `D7 留存` >= 25%
- `搜索 Top3 命中率` >= 70%（内部评测集）
- `同步失败率` < 3%

---

## 3. 周度冲刺计划

## Week 1 - 数据与闭环底座

### 目标

- 先把“看得见漏斗”搭起来，避免后续盲做功能。

### 交付项

1. 事件模型落地（扩展 + 服务端）：
   - `conversation_extracted`
   - `conversation_synced`
   - `recommendation_exposed`
   - `recommendation_clicked`
   - `knowledge_reused`
2. 在 Dashboard 增加基础漏斗看板（按天/按来源）。
3. 定义推荐服务协议（输入、去抖、超时、降级策略）。
4. 补一套 50 条真实查询评测集（技术问答为主）。

### KPI

- 事件采集覆盖率 >= 95%
- 漏斗面板可稳定展示最近 7 天数据

### 验收标准

- 可以在 1 个页面看到：提取 -> 同步 -> 推荐曝光 -> 点击 -> 复用完整链路。
- 任一环节失败能追踪到具体错误原因和来源。

### 风险与回滚

- 风险：埋点影响主链路性能。
- 回滚：埋点异步化，超时直接丢弃，不阻塞入库。

---

## Week 2 - 主动推荐 MVP（扩展侧）

### 目标

- 在用户输入时提供“可点可用”的历史知识建议。

### 交付项

1. 扩展输入监听（ChatGPT + Claude）：
   - 输入 >= 10 字触发
   - 300ms 去抖
   - 1.5s 搜索超时
2. 推荐面板：
   - 展示标题、摘要、类型、标签
   - `复制` 与 `插入输入框` 两个动作
3. 推荐降级：
   - 搜索失败时自动隐藏面板
   - 服务不可达不打扰用户
4. 增加可关闭开关（按站点记忆）。

### KPI

- 推荐曝光率 >= 35%
- 推荐点击率 >= 8%（MVP 基线）

### 验收标准

- 用户在支持站点连续输入时，推荐面板稳定出现/消失，无明显卡顿。
- 复制/插入成功率 >= 98%。

### 风险与回滚

- 风险：页面 DOM 频繁变化导致注入不稳定。
- 回滚：保留“仅弹窗提取”模式开关，推荐功能可独立关闭。

---

## Week 3 - 搜索质量升级（语义混排）

### 目标

- 提升“相似问题”检索能力，减少只靠关键词匹配。

### 交付项

1. 接入向量索引能力：
   - 入库时生成 embedding
   - 支持增量更新与删除同步
2. 实现混合检索：
   - 关键词召回 + 向量召回
   - 简单加权重排（title/summary 命中加权）
3. 评测体系：
   - Top1/Top3 命中率
   - 平均响应时间 P95
4. 面板命中解释（轻量）：
   - 显示“关键词匹配”或“语义匹配”。

### KPI

- Top3 命中率 >= 70%
- 推荐检索 P95 < 400ms（本地/近端服务）

### 验收标准

- 对评测集中“同义改写问题”，能稳定召回历史知识。
- 不影响现有关键词检索功能与接口兼容性。

### 风险与回滚

- 风险：embedding 成本与时延增加。
- 回滚：保留关键词模式开关，语义检索按环境变量启用。

---

## Week 4 - 上线准备（安全 + 商业化最小闭环）

### 目标

- 让产品具备“小规模公开测试”条件。

### 交付项

1. 安全基线：
   - 生产模板默认开启 `REFINE_API_TOKEN`
   - 未授权请求统一拒绝与提示
2. 计费前置能力（不强推付费）：
   - Free 配额统计（如 100 条）
   - 超限提示与升级引导位
3. 激活引导：
   - 安装后首日任务流（提取 1 条 -> 搜索 1 次 -> 使用 1 次）
4. 发布检查清单：
   - 可观测性、错误告警、回滚脚本、FAQ。

### KPI

- 激活率 >= 55%
- D7 留存 >= 25%
- 同步失败率 < 3%

### 验收标准

- 从新安装到首次复用，全流程可在 5 分钟内完成。
- 在云端不可达、鉴权失败等场景下有明确错误反馈。

### 风险与回滚

- 风险：鉴权开启后影响历史用户接入。
- 回滚：保留灰度窗口（开发环境免鉴权，生产强制鉴权）。

## 5. 每周评审模板

每周固定输出 1 页复盘：

1. 本周目标完成度（%）
2. KPI 实际值 vs 目标值
3. 线上主要问题 Top 3
4. 下周风险与资源诉求

---

## 6. 完成定义（Definition of Done）

一个功能仅在以下条件全部满足后视为完成：

1. 通过自动化测试与关键手测用例。
2. 上线后可观测（有事件、有错误日志）。
3. 文档已更新（API/交互/开关说明）。
4. 可回滚（开关或版本回退路径明确）。
